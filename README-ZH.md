# Reference Journal Adapter

**目标期刊没有可用的 Zotero 样式？根据期刊要求，适配并验证可安装的 CSL 文件。**

准备投稿时，可能发现期刊只提供 EndNote 样式，或者 Zotero 样式库中找不到对应期刊。使用 Zotero 管理文献的作者，需要一份能够生成目标格式的 CSL 样式，才能继续自动插入引用、更新编号和生成参考文献表。

`reference-journal-adapter` 围绕这一需求，协助确认期刊格式、选择合适的已有样式进行适配，并通过输出检查与 Zotero 实际渲染确认，形成可安装、可维护的 CSL 文件。

> 🎯 确定目标期刊 → 📋 确认格式 → 🛠️ 适配样式 → 🔎 检查输出 → 📦 安装使用

## ✨ 可以完成哪些工作

**主要用途是为缺少可用 Zotero 样式的目标期刊适配 CSL**，同时支持核对和修订已有样式。

| 遇到的情况 | Skill 提供的帮助 |
|---|---|
| **期刊只提供 EndNote 样式** | 结合其可观察输出与期刊要求，适配 Zotero 使用的 CSL |
| **Zotero 样式库中找不到对应期刊** | 寻找格式接近的父样式，按目标要求修改并验证 |
| **已有相近样式，但部分格式不同** | 调整作者、标点、页码、DOI/PMID 等具体差异 |
| **已有 CSL 的输出不符合要求** | 定位问题，提出修改方案并检查修订结果 |
| **找到对应样式，希望确认是否适用** | 对照期刊要求，核对正文引用与文后参考文献 |

### 为什么使用这个 Skill？

自行修改 CSL 时，一处看似简单的调整可能涉及多个输出分支。例如，增加 PMID 后，还需要检查只有 DOI、只有 PMID 和两者均缺失时的标点；修改作者截断规则后，还需要比较不同作者数量下的输出。

这个 Skill 将适配过程组织为可逐项核对的工作流：

- **规则有依据**：重要格式关联到期刊材料，存在冲突时先明确采用哪种要求。
- **修改有基础**：选择行为接近目标的父样式，围绕实际差异进行调整。
- **结果可比较**：保留修改前后的输出，检查目标变化及相关行为。
- **交付可追溯**：提供 CSL、验证记录与来源归属，便于安装和后续维护。

<a id="案例为-jcth-适配-zotero-样式"></a>

## 🔬 案例：为 JCTH 适配 Zotero 样式

本案例根据 **Journal of Clinical and Translational Hepatology（JCTH）** 的格式要求，以 **Taylor & Francis AMA** 为父样式进行适配，形成可供 Zotero 使用的 CSL 文件。

### 看看实际变化

以下为同一条受控测试记录的处理器输出：

**调整前**

[1] Alpha A. Controlled article with both identifiers. *J Delib Long Med*. 2024;12(3):101-109. doi:10.1234/JCTH.TEST.001

**调整后**

[1] Alpha A. Controlled article with both identifiers. J Delib Long Med 2024;12(3):101–109. doi: 10.1234/JCTH.TEST.001, PMID: 90000001.

这条结果展示了期刊名字体、标点、页码连接符及 DOI/PMID 输出的调整。

案例还覆盖了以下格式：

| 内容 | 适配后的表现 |
|---|---|
| 正文引用 | 数字上标、按编号排序、逗号分隔与连续编号压缩 |
| 作者数量 | 六名以内列全；超过六名时列前六名，再接斜体 *et al.* |
| 标识符 | 分别处理 DOI+PMID、仅 DOI、仅 PMID 和两者均缺失 |
| 文献类型 | 按类型组织期刊文章、书籍、章节等条目的字段与标点 |
| 文后布局 | `[n]` 编号、悬挂对齐、双倍行距 |

### 验证与使用

适配后的 CSL 已完成结构检查与引用、参考文献输出对比。案例还保留了 Zotero/Word 中的实际渲染记录，展示上标引用、参考文献编号、悬挂对齐、双倍行距及作者截断等效果。

案例文件包含父样式、适配结果、受控测试记录和验证说明，可以查看具体变化，也可以按照案例步骤回放。

## 🚀 安装与首次使用

### 1. 安装 Skill

将包含 `SKILL.md` 的完整文件夹放入个人 Skills 目录：

```text
~/.agents/skills/reference-journal-adapter/
```

Windows 路径示例：

```text
C:\Users\<用户名>\.agents\skills\reference-journal-adapter\
```

Codex 会自动发现该目录中的 Skill；如果尚未显示，可以重启 Codex。详见 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。

### 2. 准备任务材料

从手头已有的内容开始：

| 材料 | 可以提供什么 |
|---|---|
| 目标期刊 | 期刊名称、官网或作者指南链接 |
| 格式依据 | 参考文献要求、投稿模板、示例条目或 EndNote 样式 |
| 现有样式 | 正在使用的 CSL，或格式接近的候选样式 |
| 使用范围 | 主要涉及的文献类型，以及最需要解决的格式问题 |

可以选择由助手检索官方材料、使用提供的本地文件，或结合两种方式。助手会根据当前任务提出资料获取方案。

### 3. 发起第一次协作

```text
使用 $reference-journal-adapter，为下面的期刊准备 Zotero CSL 样式。

目标期刊：
……

目前情况：
期刊只提供 EndNote 样式，在 Zotero 样式库中没有找到对应样式。

资料获取方式：
优先检索期刊官网，需要补充材料时再说明。

主要文献类型：
期刊文章、书籍章节。

已有材料：
……

请先整理格式要求和适配方案，确认后再修改 CSL。
```

<a id="怎样完成一次适配"></a>

## 🧭 怎样完成一次适配

### ① 确认目标与格式要求

明确目标期刊、需要支持的文献类型和已有材料，再将期刊要求整理为可以检查的规则，例如：

- 正文引用是否为上标，怎样排序和压缩连续编号。
- 作者列出几名，何时使用 *et al.*。
- 期刊名、卷期、页码和标识符怎样组合。
- 书籍、章节等类型采用什么结构。

涉及输出的来源冲突会集中列出，在确认规则后继续实施。

### ② 选择合适的样式基础

先检查是否已有对应的官方样式，再比较候选样式的实际行为。

选择依据包括正文引用、文后布局、文献类型覆盖和需要修改的范围。已有独立 CSL 也可以直接作为检查与修订的基础。

### ③ 建立基线并完成修改

使用代表性记录运行原样式，保留调整前的输出，再围绕确认的差异修改工作副本。

正文引用和文后参考文献分别检查，便于发现局部修改对其他输出的影响。

### ④ 在 Zotero 中确认

机器检查完成后，助手会提供候选 CSL 和简短的 Zotero 检查清单。

按照清单在 Zotero/Word 中观察关键结果，反馈必要的截图或输出；需要调整时，围绕受影响的部分继续修改和确认。

### ⑤ 整理最终文件

实际渲染确认后，交付 CSL、验证摘要与来源归属，并记录最终文件的校验值，便于确认安装与验证使用的是同一份文件。

<a id="最终会得到什么"></a>

## 📦 最终会得到什么

一次适配的交付通常包括：

| 交付物 | 用途 |
|---|---|
| **可安装的 `.csl` 文件** | 在 Zotero 中使用目标格式 |
| **格式规则清单** | 查看采用了哪些要求及其依据 |
| **来源与样式归属记录** | 追溯指南、父样式和相关许可 |
| **测试数据与预期结果** | 复查当前行为，支持后续维护 |
| **验证摘要** | 查看检查结果与实际渲染记录 |
| **最终文件校验值** | 确认安装、测试与交付对应的文件 |

交付内容随任务范围调整。局部核对可以聚焦于指定问题，完整适配则保留从规则到最终文件的证据链。

## 🛠️ 工具与进阶使用

日常使用通过自然语言发起，由助手组织资料、修改和验证。

配套脚本承担可重复的检查与文件操作：

| 脚本 | 用途 |
|---|---|
| `render_csl.js` | 渲染受控记录的引用与参考文献输出 |
| `compare_csl_results.js` | 对照预期结果，区分通过、已知差异和意外回归 |
| `validate_csl.py` | 检查 XML、RELAX NG 与 Schematron |
| `promote_verified_artifact.py` | 校验文件哈希并保持字节一致地交付 |

渲染使用 Node.js 与 citeproc；结构验证使用 Python、lxml 和 rnc2rng。每个适配任务记录所用处理器、locale 和 schema 的版本，优先复用已有兼容环境，需要安装时先说明依赖与位置。
